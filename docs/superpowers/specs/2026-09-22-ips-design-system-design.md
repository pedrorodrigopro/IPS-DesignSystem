# IPS Design System — Design Spec

**Date:** 2026-09-22  
**Author:** Pedro Rodrigo  
**Status:** Approved

---

## Overview

A standalone React component library and Storybook instance for the IPS (ProFinda) design system. Lives in the `IPS-DesignSystem` repository. Independent from `premiumui` — components are built here first and consumed by `premiumui` via npm. Storybook serves as both the component documentation and the primary prototyping surface for the design team.

---

## Goals

1. Give the design team a living, interactive component library that mirrors the Figma IPS-Components file
2. Replace static HTML prototypes with composable Storybook stories that have real interactions
3. Establish a path for `premiumui` to consume components from a single source of truth
4. Demonstrate that the design team is leading AI-assisted product development

---

## Non-goals

- Does not replace Figma for ideation and early exploration — Figma stays for sketching and swapping ideas
- Does not immediately replace all 90 components in `premiumui` — migration is gradual
- Does not require a backend or auth to prototype screens

---

## Architecture

### Approach

Vite in library mode + Storybook 8 + Figmagic. Same stack as `premiumui` (React 19, TypeScript, SCSS Modules) so patterns are familiar and handoff is straightforward.

### Repository structure

```
IPS-DesignSystem/
├── src/
│   ├── tokens/              # Auto-generated by Figmagic from Figma IPS-Components file
│   │   ├── colors.ts
│   │   ├── spacing.ts
│   │   ├── typography.ts
│   │   └── radii.ts
│   ├── styles/              # Global SCSS — converts tokens to CSS custom properties
│   │   ├── tokens.scss
│   │   └── reset.scss
│   ├── components/          # One folder per component
│   │   ├── button/
│   │   │   ├── button.tsx
│   │   │   ├── button.module.scss
│   │   │   ├── button.stories.tsx
│   │   │   └── index.ts
│   │   ├── card/
│   │   ├── sidepanel/
│   │   ├── modal/
│   │   └── index.ts         # Barrel export for the whole library
│   └── prototypes/          # Storybook stories that compose full screens
│       └── booking-flow.stories.tsx
├── figmagic.json            # Points to Figma IPS-Components file (adFvaOeh8E3AKLFKRjYD3r)
├── vite.config.ts           # Library mode — outputs ESM + CJS, no app bundle
├── package.json             # name: "@ips/design-system"
└── .storybook/
```

### Key toolchain

| Concern | Tool | Notes |
|---|---|---|
| Bundler | Vite (library mode) | Outputs ESM + CJS for npm consumption |
| Documentation & prototyping | Storybook 8 | Same version as premiumui |
| Styling | SCSS Modules + CSS custom properties | Matches premiumui patterns |
| Design tokens | Figmagic → Figma IPS-Components | Single `yarn figmagic:sync` command |
| Language | React 19 + TypeScript | Matches premiumui |
| Package name | `@ips/design-system` | Consumed via `file:../IPS-DesignSystem` initially, npm later |

## Design tokens

Tokens are sourced from the Figma IPS-Components file (`adFvaOeh8E3AKLFKRjYD3r`) via Figmagic. The sync command (`yarn figmagic:sync`) outputs TypeScript token files to `src/tokens/`. A SCSS build step converts these to CSS custom properties in `src/styles/tokens.scss`, which are loaded globally in Storybook and exported with the package.

Token categories: colors, spacing, font sizes, font families, font weights, line heights, letter spacings, radii.

---

## Prototyping workflow

**Figma role:** Early ideation, exploration, visual iteration, historical reference. Figma files are not deleted or deprecated — they remain the sketching surface.

**Storybook role:** Validation and stakeholder presentation. Once a design direction is decided in Figma, it is implemented as a Storybook story using real components.

**Flow:**
1. Sketch in Figma as usual
2. Decide on direction
3. Build/update components in `IPS-DesignSystem`
4. Compose a prototype story
5. Share Storybook URL with stakeholders

## Phased roadmap

### Phase 0 — Scaffold (day 1)
- Initialise `IPS-DesignSystem` with Vite library mode, Storybook 8, Figmagic
- Sync tokens from Figma
- Build Button end-to-end to prove the pipeline works

### Phase 1 — Atoms & molecules (weeks 1–2)
- All atoms listed above with full variant coverage matching Figma
- Figma design link in each story via Storybook Figma addon
- Molecules: Dropdown, Card, Toast, KPI card

### Phase 2 — Organisms & first prototype (weeks 3–4)
- Sidepanel/Booking, Modals
- First composed prototype story: booking flow screen

### Phase 3 — Deploy & demonstrate (ongoing)
- Deploy Storybook to GitHub Pages or Netlify (free tier)
- Share with design and product teams
- Use OpenCode to build new prototype screens — demonstrating AI-led design workflow

## Consumption in premiumui

Initially: add `"@ips/design-system": "file:../IPS-DesignSystem"` to `premiumui/package.json`. Components are imported normally:

```tsx
import { Button } from "@ips/design-system";
```

When ready to publish: push to npm registry (private or public) and update the dependency reference.
